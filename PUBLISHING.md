# Publishing to addons.mozilla.org

How to get Scroble Discogs onto [addons.mozilla.org](https://addons.mozilla.org) (AMO), and how
to ship updates afterwards. Two routes: the **web flow** (recommended for the first submission,
where the listing metadata is filled in) and the **CLI** (fastest for updates).

Firefox extensions must be signed by Mozilla to install permanently — even self-distributed
ones. Both routes below do the signing.

---

## 0. Before every submission

```bash
npm install
npm test          # must be green
npm run lint      # must be 0 errors, 0 warnings — this is AMO's own validator
npm run build     # → web-ext-artifacts/scroble_discogs-<version>.zip
```

`npm run lint` runs exactly what AMO runs at upload time. Fixing it here saves a round trip.
(Don't pass `--self-hosted` when publishing on AMO — that flag suppresses the checks that only
apply to listed add-ons.)

Check `manifest.json`:

- **`version`** must be higher than anything previously uploaded. AMO rejects a re-used version
  number permanently — even if that version was deleted. Bump `package.json` to match.
- **`browser_specific_settings.gecko.id`** (`scroble-discogs@vo1dee`) must never change. It is
  the add-on's identity on AMO and the thing that makes an upload an *update* rather than a new
  add-on.
- **`strict_min_version`** is `142.0`. `data_collection_permissions` needs Firefox 140+, so
  don't lower it below that.
- **`data_collection_permissions.required`** declares `authenticationInfo` and
  `browsingActivity`. These drive Firefox's install prompt and the reviewer's expectations —
  they must match what the code actually does, and what [PRIVACY.md](PRIVACY.md) says.

The built `.zip` contains only `manifest.json`, `src/` and `icons/` — `web-ext-config.mjs`
keeps tests, docs and tooling out of it. Check with `unzip -l web-ext-artifacts/*.zip`.

## 1. Developer account

Sign in at <https://addons.mozilla.org> with a Mozilla account (the same one Firefox Sync uses,
or a new one). Accepting the developer agreement on first submission turns it into a developer
account — there's no separate registration.

Two-factor authentication is required before you can submit.

---

## 2. First submission — the web flow

Go to **<https://addons.mozilla.org/developers/addon/submit/>**.

### a. Distribution

- **On this site** — listed publicly on AMO, found by search, auto-updating. This is what you
  want for a public release.
- **On your own** — Mozilla signs the `.xpi` and hands it back; you distribute it yourself. No
  listing, no review queue for most versions. This is what `npm run sign` does.

### b. Upload

Upload `web-ext-artifacts/scroble_discogs-0.1.0.zip`. The validator runs immediately; since
`npm run lint` was clean, it should pass.

Then it asks **"Do you need to submit source code?"** → **No**. Source code is only required
when the shipped files are minified, obfuscated, or generated by a build tool. This extension
ships plain, readable ES modules with no build step.

Select compatibility: **Firefox** (desktop). Android is a separate checkbox — leave it off
unless you've actually tested it there.

### c. Listing details

| Field | Notes |
|---|---|
| **Name** | Scroble Discogs |
| **Add-on URL** | The `addons.mozilla.org/addon/<slug>` slug. Permanent — choose carefully |
| **Summary** | 250 characters, shown in search results. The manifest description works: *Scrobble vinyl to Last.fm from Discogs release pages, one click per side.* |
| **Description** | The long text on the listing page. Adapt the top of [README.md](README.md) — what it does, the four popup tabs, the dry-run safety note. Plain language; AMO reviewers read this |
| **Categories** | Up to two. *Music* fits |
| **Support email / website** | Required. A repository issues URL is fine for the website |
| **License** | Pick one. Needed for the listing; the repo has no `LICENSE` file yet, so add one that matches |
| **Privacy policy** | **Required here** — the extension declares data collection. Paste the contents of [PRIVACY.md](PRIVACY.md) |
| **Screenshots** | Optional but worth it: the tracklist picker over a release page, and the popup's Search tab |

### d. Review

Submission is confirmed by email. Listed add-ons are scanned automatically and most go live
within minutes to a few hours; a human review is triggered by riskier patterns (remote code,
broad host permissions, obfuscation) — none of which apply here. If a reviewer does write, they
ask about data handling, so keep PRIVACY.md accurate.

## 3. Updates

Bump the version in **both** `manifest.json` and `package.json`, then either:

**Web** — your add-on's page on AMO → *Upload New Version* → upload the new `.zip`. It inherits
the listing metadata; you only add release notes.

**CLI** — get API credentials at <https://addons.mozilla.org/developers/addon/api/key/>, then

```bash
npx web-ext sign --channel=listed \
  --api-key=YOUR_JWT_ISSUER --api-secret=YOUR_JWT_SECRET
```

`--channel=listed` uploads to the AMO listing; `--channel=unlisted` (what `npm run sign` uses)
signs for self-distribution instead and returns the `.xpi`.

> Keep those credentials out of the repo — `.gitignore` covers `.env`, but never paste them
> into a script that gets committed. Regenerate them at the link above if they leak.

---

## 4. Self-distribution, as an alternative

You don't have to list on AMO. `npm run sign -- --api-key=… --api-secret=…` produces a signed
`.xpi` in `web-ext-artifacts/` that installs permanently in any Firefox. Add an `update_url` to
`browser_specific_settings.gecko` if you want those installs to auto-update from your own
server. Unlisted versions skip the review queue.

---

## Things that commonly go wrong

- **Re-used version number.** Permanent rejection; bump and rebuild.
- **Changed extension id.** AMO treats it as an entirely new add-on, and existing users never
  get the update.
- **Missing privacy policy** while declaring data collection. Blocks the submission.
- **Test files in the package.** Not fatal, but reviewers ask about anything that isn't needed
  at runtime. `web-ext-config.mjs` already excludes them — don't quietly widen what ships.
- **Data declarations drifting from the code.** If the extension starts talking to a third host,
  update `data_collection_permissions`, PRIVACY.md, and the listing together.
